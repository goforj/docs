Where each accent sits on the heat

Steel announces its temperature by color, and smiths read it by eye — which gives this family a real organising principle rather than an arbitrary hue pick. Forge, Steel, and Temper deliberately share Molten's exact accent; they improve it on other dials, so they sit at the same point on the scale. Edge is the only variant that moves the temperature — and Temper is the only one that adds a second color, one stop further up the same scale.

Molten the anchor

Maximum confidence · minimum chrome

Near-pure black, one accent taken from steel at forging temperature, display type set enormous and tight, almost no borders or cards. Hierarchy carried entirely by scale and space.

The variants that follow each fix one specific thing this gets wrong, without giving up what makes it good. Compare them against this, not against each other. Temper combines two of the fixes and is the one to look at last.

Molten Forge fixes elevation

Molten with somewhere to put things

Molten's biggest practical problem is that pure black has no room underneath it. Every card, code block, screenshot, and Lighthouse panel has to sit on the same plane as the page, so the whole thing flattens out and imported images look like holes punched in the page.

Forge lifts the ground to #0C0A0E and builds a real elevation ladder above it — ground, ground-alt, surface, surface-2 — each step clearly distinguishable. Radius goes from 2px to 8px so cards read as objects rather than outlined regions, and surfaces get a soft shadow. Same accent, same type, same attitude; it just has depth now.

Molten Steel fixes the color jobs

Hot for action · cold for navigation

In Molten, orange is the button, the link, the active sidebar item, the TOC marker, the inline code, and the callout border. When one color means everything, it stops meaning anything — and on a docs page with fifty links, it becomes noise.

Steel splits the work. Molten orange is reserved for action: primary buttons, the install command, CTAs. A desaturated steel blue takes navigation: links, active sidebar, TOC, breadcrumbs. Look at the sidebar and TOC in the docs mock below — the orange now only appears where you can actually do something.

Molten Edge fixes flatness

Hotter · tighter · harder

The opposite response to the same complaint. Rather than lifting the ground, Edge commits harder: ground drops to #060509, the accent moves hotter and more saturated, radius goes to zero, and tracking tightens to -0.058em with the headline scaled up.

The fix for flat black isn't more gray — it's texture. A fine film-grain overlay sits on the hero, which stops the large dark areas reading as dead pixels and gives the page a physical quality that flat black can't. Gold returns at peak heat for hover and focus states.

Molten Temper the hybrid

Forge's depth · Steel's discipline · warm throughout

Tempering is the last heat treatment steel gets — it takes metal that is hard but brittle and makes it tough enough to actually use. That is what this does to Molten: Forge's elevation ladder plus Steel's job split, with the cool color thrown out.

Steel's weakness was that its blue landed close enough to the VitePress indigo you're escaping to feel like a step backwards. Here, navigation goes to gold instead. It stays inside the heat metaphor, and at 12.3:1 it is nearly twice as legible as the orange — which matters, because links are the most numerous colored thing on a docs page.

The honest weakness: two warm colors are only 28.5° apart in hue, so they will not separate on hue alone the way orange and blue did. A second rule carries the load — action is always a filled shape, navigation is always text or a line. Different form, not just different color.

RoleColorFormWhere it appears
Action Molten orange Always filled Primary button, install command prompt, version badge, h1 accent rule
Navigation Temper gold Always text or line Body links, active sidebar item, TOC marker, active nav, callout rule
Reference Warm frame, bright ink Filled, but ink is white Inline code chips — salient, never mistakable for a link or a button
Neither Neutral surface Surface + hairline Table headers, code block chrome, disclosure controls

The reference row is where this earns its keep. Inline code is the first thing developers scan for, so it has to be loud — but Molten paints it in the accent, which means a paragraph with seven code references lights up like an alert and every chip looks clickable. Temper keeps the warm frame and the weight, and switches the ink to white. Salience comes from material, not from a semantic color — so code can shout without lying about what it is. How loud should a backtick be?

Same sentence, seven code references, two treatments. Cut from five: Full accent and Navigation gold were rule violations rather than taste calls — a filled orange chip is the definition of an action in this system, and a gold one is the definition of a link — while Neutral dimmed a string the reader has to transcribe exactly.

What is left is a question about design language. Inline code is not a semantic role; it is a typographic register — it says "this is a literal quotation from the machine's language", not "this will do something if you touch it". Roles get hue. Registers get typography and material, and inline code already owns the strongest register signal there is: it changes typeface. High contrast spends no accent and still shouts, and it stays calm across a code-dense page. Warm frame is more distinctive but needs a fourth rule to justify itself. Whichever you pick drives the docs mock below.

Apps

Start with one app. Add another only when the Project needs another runnable boundary.

That rule keeps GoForj simple: one Project, shared application behavior under internal/, and clear app composition under app/. See runtime topology for how they split at deploy time.

The default shape

Every Project has a default app named app. Set STORAGE_PHOTOS_DRIVER to s3 in production and local in development — forj dev reads .env, then forj build compiles the selected drivers into bin/app:

internal/photos/service.go
// Services depend on contracts, not drivers.
type Service struct {
    disk storage.Storage
}

func (s *Service) Store(ctx context.Context, in UploadInput) (Photo, error) {
    path := photoPath(in)
    if err := s.disk.WithContext(ctx).Put(path, in.Body); err != nil {
        return Photo{}, fmt.Errorf("store photo: %w", err)
    }
    return Photo{Path: path}, nil
}
NoteApps in a multi-app Project share one repo, one Go module, and everything under internal/. No RPC ceremony, no duplicated plumbing.

Syntax — transposed from your current theme

Your site runs github-dark today. I pulled its real token colours off the rendered page rather than guessing, and the reason its contrast works is structural: every token is a high-luminance pastel, the hues sit far apart, plain text is near-white, and comments are the only dim element. The three transpositions below preserve that luminance profile and move hue into the Temper family — each token lands within about one contrast point of the github-dark original, and where they differ they are brighter, because Temper's code surface is darker than GitHub's.

Switch to GitHub (current) in the header to A/B against the real thing. One fidelity detail carried through: github-dark colours Go built-in types like error with the keyword colour, and nil as a constant — Forge keeps that, while Ember and Neon separate built-ins out as a deliberate improvement.

Note

Apps in a multi-app Project share one repo, one Go module, and everything under internal/. No RPC ceremony, no duplicated plumbing.

Tip

Run forj route:list instead of scrolling startup logs — it is the source of truth for the HTTP surface.

Warning

Changing DB_DRIVER after migrations have run requires a fresh migration path.

Danger

forj make:controller --remove deletes the file and unwires it. There is no undo.

What does --dry-run print?
Every file the generator would create, every file it would modify, and the exact wiring lines it would insert — with no changes written to disk.

Steps

  1. Create the Project

    Run forj new and pick your components. Nothing you skip gets rendered.

  2. Bring it up

    forj dev builds the binary, starts containers, runs migrations, and watches for changes.

  3. Generate a feature

    forj make:controller photos writes the file and the wiring beside the service that owns it.
