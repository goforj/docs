Status is a third system

Action

Always filled. It marks the one thing on a view that is the primary move. It is never text on a transparent background: an orange word looks like a link, and links are gold.

Ink on the accent must be --gf-on-accent, not white

White on the accent fill measures and fails AA. The near-black measures . On a fill this saturated that is not a stylistic choice, it is the only legible option.

Navigation

Always text or a line, never a fill. The second half of the rule matters more than the first: gold means this takes you somewhere.

Details that are decisions

Ligatures are off. Go reads better without => and != fused into glyphs that do not exist in the source.

Inline code sits at 0.92em, not the more common 0.85em. Mono has a larger x-height than Inter at the same nominal size, so a smaller value looks small and bulky at once. 0.92 is where the two optically match.

Emphasis in a headline is <em>, and it means the accent lands there. font-style stays normal — the accent is the emphasis, and italicising as well says it twice.

Body is 400, emphasis is 600. No 700 outside the display face, and no 800 or 900 anywhere. Heavy weights were doing emphasis work that colour should not have been doing either; a label at 850 in navigation gold said “important” three times.

Planes

Depth, and how it is measured

Use ΔL*, not WCAG ratio, to judge whether two surfaces separate

WCAG contrast ratio is a text legibility metric. Its +0.05 flare constant dominates the numerator when both luminances are near zero, so any two dark surfaces collapse to roughly 1.0–1.2:1 no matter how different they look. ΔL* (CIE L*, perceptual lightness) tracks what the eye reports for large flat areas. Under 1 is invisible, 2–3 is a subtle step, 5+ is a clear plane change. This is written down because the original verification checked WCAG only, passed every palette, and missed a code surface pointing the wrong way.

Break it yourself

That gap is the entire argument for measuring surfaces in L*, and it is why a verification pass that checked only WCAG passed a code surface nobody could see.

The stack, measured

The code well lands back on the canvas value exactly. Code is a hole through the column to the page ground underneath — the same depth it would have had if the column were never lifted. That fell out of the arithmetic rather than being designed, which is usually a sign the structure is coherent.

Why the column is lifted

There was nowhere to put the code. A near-black page has about three L* units of room beneath it — even pure black buys less separation than raising the code block did. The code well was never a contrast failure; it had plenty of separation and was pointing the wrong way, because there was nowhere else to go. Lifting the column creates the room.

Colour needs light. Perceived chroma of the violet neutral measures ~1.9 at the deep ground and ~7.8 at the column. Lower down, the brand tint is in the hex and absent from the eye.

Near-black halates. White text on a very dark ground blooms slightly, especially on OLED. At the column’s lightness it stops.

Measured from the column

A token is only meaningful relative to the ground it was calibrated against. --gf-surface is a +8.6 step from the column. Used on a marketing page, where the ground is the deep value, the same token becomes a +13.7 step — 1.6× the intended lift across a large area, which reads as pale blocks rather than panels. On the deep ground, content sits at --gf-ground and takes the same step the column takes.

Code is a well, not a card

Every tool the audience uses all day — editor, terminal, diff, gist — renders code in a recessed dark field. A code block styled as a card that happens to contain code stops reading as a viewport into another system. Chrome recedes, content advances: the tab strip on a code group must never be the lightest plane in the component.

Two known collisions

Ember’s function colour is #FFC24D — the same hex as navigation gold. This is contained to code, where the syntax system governs rather than the four-role table, so it is acceptable. But it means an automated check cannot distinguish “gold used correctly in code” from “gold used wrongly as emphasis”. That one case needs a human.

The same is true of warning amber () against navigation gold (). They are close enough that a colour audit written against one will flag the other. Both are legitimate in their own roles — but any automated check over this palette will produce false positives on these two pairs, and reviewers should expect that rather than chase them.

Two Go fidelity details

Both confirmed against live output, and both easy to get wrong: Go built-in types (error, string) take the keyword colour, not a type colour; and nil is a constant, not a keyword.

Comments were lifted

github-dark sets comments at #6A737D, which measures 3.9:1. Ember lifts them to #8A8196 at 5.1:1. Comments are content people actually read, and dimming them below AA treats them as decoration.

Surface rules

Highlighted lines are navigation — a gold left rule plus a wash, because the highlight says “look here”, not “do this”. Diffs use status colours, not brand ones. Copy is an action: its resting state is a neutral ghost, and only the completed state fills with the accent, because a completed action is legitimately an action.

A shell command in a marketing card is still code. It goes in a well at the well’s depth, in the Ember palette — $ in the action colour, the binary in the function colour, arguments in plain. The failure mode this replaced was the whole command in navigation gold at weight 900, which made it look like a link that had been shouted.

Components

Applied, using the real tokens

Action versus navigation

A body link is navigation: gold, underlined, no fill. A button is filled. A markdown link styled as a button must be excluded from the prose link rule, or it inherits gold and ends up as gold ink on an orange fill.

Reference — inline code

Set STORAGE_PHOTOS_DRIVER to s3 in production and local in development. The forj dev command reads .env, then forj build compiles the selected drivers into bin/app.

Seven references in two sentences is the stress test. Inline code is not a semantic role at all — it is a typographic register. It says “this is a literal quotation from the machine’s language”, not “this will do something if you touch it.” Monospace and restrained warm ink make that register visible without wrapping every literal in an interactive-looking box.

The code well

// Package photos keeps upload workflows independent from configured Drivers.
package photos

import (
    "context"
    "fmt"
    "time"
)

const maxUploadBytes = 25 << 20

// Photo identifies an uploaded object without exposing its backing Driver.
type Photo struct {
    ID        string    `json:"id" db:"id"`
    OwnerID   string    `json:"owner_id" db:"owner_id"`
    CreatedAt time.Time `json:"created_at"`
}

// Service keeps photo workflows portable across storage and cache Drivers.
type Service struct {
    disk  storage.Storage
    cache cache.Cache
}

// Store persists an upload before invalidating its cached photo state.
func (s *Service) Store(ctx context.Context, name string, body []byte) (Photo, error) {
    if len(body) > maxUploadBytes {
        return Photo{}, ErrTooLarge
    }

    if err := s.disk.Put(ctx, name, body); err != nil {
        return Photo{}, fmt.Errorf("store photo %q: %w", name, err)
    }

    s.cache.Forget(ctx, "photos:"+name)
    return Photo{ID: name, CreatedAt: time.Now()}, nil
}

Every role in the mapping above appears here, which is the point of the sample: comment, keyword, built-in, type, function, string, number, constant, struct-tag key, format verb and punctuation. Two fidelity details worth checking against your own theme — error, string and byte take the keyword family rather than a type colour, and nil is a constant, not a keyword.

States

Rest is not the only state

Focus was missing entirely

Until this section was written, every focusable element on the site computed to outline-style: none — links, sidebar items, the copy button, search. Keyboard users had no visible focus indicator at all. That is WCAG 2.4.7 Focus Visible, a Level AA criterion, and it is the most serious defect this work has turned up. It came from a base-theme reset rather than a decision, which is exactly why it survived: nobody chose it, so nobody reviewed it.

The focus ring

Focus is neither action nor navigation — it is system feedback about where you are. It uses the accent because “you are about to act here” is the closest of the three roles, and because 2px of accent clears the 3:1 non-text contrast floor on every Temper ground with room to spare.

Space

Rhythm and measure

Undocumented constraints erode first. The spacing steps and the line-length rule were both being followed in the stylesheet and written down nowhere.

Spacing

A six-step scale. Not a strict 4px grid — the steps widen as they grow, because equal ratios read as equal spacing and equal increments do not.

Measure

Prose is capped at 66ch. Captions and secondary text run to 72ch because they are shorter overall and the extra width costs less than the extra wrapping.

This paragraph is set at the 66ch measure. Beyond roughly this width the eye loses the start of the next line on the return sweep, which is the actual reason for the rule — not aesthetics.

This one is uncapped. On a wide screen it will run past the point where returning to the next line stays effortless, and you can feel the difference between this sentence and the one above it as the lines get longer and longer and the return sweep gets harder to land accurately.

Durations sit between 120ms and 280ms. Below 120ms the change reads as a jump; above 280ms it reads as a wait. The site's own transitions are 150–180ms.

The rule, not the value

A transition that forgets the gate is not a slow transition — it is an accessibility failure for someone with a vestibular disorder. This is the one subsystem where the correct default is nothing moves.

Stress

The system under hostile content

Every specimen above uses ideal content. Real failure arrives as content nobody designed for — and those are exactly the cases where someone invents an off-system solution because the system appeared not to cover them.

Light mode

Not an inversion — a different set

Use the toggle in the header. Every readout on this page recomputes from the live stylesheet, so the swatches, contrast ratios, plane tables and the elevation diagram all re-derive rather than being redrawn. That is the payoff for never having written a value down.

Gold cannot survive on white

Navigation gold measures against a white ground in light mode's own value, because it darkens to bronze (). Keeping the dark-mode gold would have put links at roughly 1.7:1 — invisible. This is the single biggest reason light mode is not an inversion: the navigation role changes hue family, and that changes how the whole palette feels.

The role colours, in this mode

Planes invert, the relationships do not

In dark mode the reading column steps up from the canvas and code cuts back down. In light mode the page is already at the ceiling, so the column stays at white and everything else steps down instead. The directions flip; the ΔL* gaps stay comparable.

Syntax is re-hued, not lightened

Ember's light palette is not the dark one darkened. Light needs different hues to clear AA on a near-white ground, so the cool anchor moves from mint to a deep teal and the warm tokens darken into brick and bronze. Toggle the mode and watch the sample block change hue, not just value.

A depiction does not flip

Every mock, plane stage, do/don't panel and gallery box on this page is a picture of the dark product. It no more inverts when you flip this page than a screenshot would, so those surfaces stay pinned to the dark tokens in both modes. The page chrome around them flips; the specimens do not. The one exception is the Ember block above, which exists to show the syntax palette and therefore has to change with it.

Pin the whole palette or none of it

The first version of this pinned only the grounds. The surfaces went dark while the ink, the nav gold and the semantic status colours stayed at their light-mode values — bronze navigation on a near-black well at 3.5:1, a “beta” badge at 3.33:1, 37 AA failures in total, none of them visible in dark mode. A depiction is a complete environment. Half a palette is not a palette.

The same bug had a second form: the plane proof read its colours once at load and the Ember sample carried a hardcoded copy of the palette, so both froze at whichever mode happened to be active first. Anything that resolves a token in script now resolves it against the element and on every repaint, which is also what makes a sample nested inside a pinned depiction inherit that depiction's palette for free.

What is still unresolved

The site's chrome is dark-only

These tokens are correct and the content column renders properly, but on goforj.dev the nav bar, sidebar and TOC still carry hardcoded dark backgrounds. Light mode there is content-complete and chrome-broken. Either the chrome gets built or the toggle comes out — the in-between state is the one thing that is not defensible, and it is still the open decision it was at the start.

Product surfaces

Apps start from the deep ground

The docs planes are not the defaults

--gf-ground does not mean “the background”. It means the surface long-form content is read on, and the lift exists for one reason: a single column of prose, read for minutes, where near-black halates under white body text. That is a reading accommodation.

An app has no single reading column — almost every surface is a working surface. Apply “content lifts” to all of them and you lift everything, and the interface goes mid-grey. This section exists because the system previously documented only the marketing and docs cases, so anyone building product would reasonably assume the docs values were defaults.

Why the docs ladder breaks

It runs out of headroom. Docs need three planes. An app needs eight — chrome, panel, row, hover, popover, dialog, plus inputs and data wells going the other way. Start at L* 8.1 and by the third nested step you are at L* 25 and everything is the same grey. Start at L* 2.9 and the whole range is available.

Data surfaces invert. Log output, terminal, code and diffs are the densest content in an app and they are wells — the darkest thing in the window, not the brightest. A log panel rendered lighter than its surroundings is the same mistake as a code block styled as a card.

The ladder

Above the panel, light mode carries elevation in shadow

Below the chrome the two modes mirror cleanly — inputs recess, and the data well still cuts furthest down, because a well is a well in either mode. Above the panel they cannot mirror. Dark mode has 97 L* of headroom over its chrome and spends nine of it on four steps; light mode's panel is already at white, leaving 1.2 L* for popover and dialog. So light mode stops using lightness there and uses shadow instead — two planes share a value and are told apart by their shadow. Flip the mode and watch the last two rows of the table below collapse onto the same number. That is the honest result, not a bug.

Every value is derived multiplicatively from --gf-ground-deep, so the violet neutral survives at each step rather than drifting toward grey. Selection uses --gf-nav-soft over the panel, exactly as the sidebar does — a wash plus a gold rule, not a lighter plate.

The rule, for handing to someone

Product surfaces

Start from --gf-ground-deep, not --gf-ground. Chrome and sidebar sit on the deep ground. Panels step up 3–5 L*. Data surfaces — logs, terminal, code, diffs — step down below the panel containing them. Selection is a gold rule plus --gf-nav-soft, never a lighter plate. The lifted ground is documentation-only.

One more thing worth checking in any product build: the neutral ramp must be the violet one at hue ~270. A generic dark-grey or blue-grey palette will read as foreign next to the landing page even when the lightness is right — and lightness is usually what gets debugged, so the hue survives unnoticed.

A caution

What will decay

Contrast ratios and token tables are the easy part, and they are settled. The part that will decay is the action / navigation / reference discipline. It is a convention, not a constraint — nothing in CSS stops someone making a link orange.

That four-row table belongs in review. It has already eroded twice in a single day of work, both times from automated passes that could not know what a table header or a button means.
